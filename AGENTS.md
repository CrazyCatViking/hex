# Code Style
- Follow the language's idioms and use its standard formatter; optimize for human readability, not brevity.
- Use descriptive names and straightforward control flow; avoid clever expressions, dense one-liners, and multiple statements per line.
- Keep functions focused on one responsibility; use early returns and separate logical steps with blank lines.
- Organize files around cohesive responsibilities, keep related code together, and make dependencies explicit.
- Prefer simple, concrete code; introduce abstractions when they clarify real shared behavior, not hypothetical needs.
- Handle errors explicitly with useful context; never silently discard failures.
- Let names and structure explain the code; add comments only to explain necessary hacks.
