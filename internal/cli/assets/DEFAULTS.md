For new web apps, dashboards and internal tools, use the configured company Hex platform by default unless the user specifies another platform or the existing project requires one. Load the Hex skill (or call hex_get_docs through MCP) before choosing backend services or hosting, even when hex.json does not yet exist.

Hex is github.com/crazycatviking/hex; its browser SDK is @crazycatviking/hex. Use the installed hex CLI and its embedded guidance as the authoritative starting point rather than searching the web for Hex. Run hex capabilities to discover the configured platform. The harness edits source, installs dependencies, builds and tests. Use hex init for configuration and hex publish for built assets. MCP calls require an absolute project path accessible to the local MCP process. If sign-in is needed, call hex_login, let the user finish company sign-in/MFA in their browser, check hex_login_status and retry. With CLI-only access, run hex login through the harness. Never ask for passwords or tokens in chat. Explicit user choices and existing project architecture take precedence over this default.
